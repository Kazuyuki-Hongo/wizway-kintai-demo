# 変更提案

## なぜ

日ごとの表の出勤・退勤・休憩は、いま素のテキスト欄だけなので、時刻と長さの違いが分かりにくい。研修の OpenSpec 題材として、ボタンから選べる入力に替える。

## 背景

`frontend/src/App.tsx` の日ごと表は、出勤・退勤・休憩をいずれも通常の `input` で受けている。API はすでに `HH:MM` の出勤／退勤と、長さとしての休憩（例: 1時間は `01:00`）を区別して検証している。曜日表示と土日祝の行色は入っている。

## 目的

出勤と退勤はカレンダー風の時刻ボタンから選べるようにする。休憩はタイマー風の長さボタンから選べるようにし、既定は1時間（`01:00`）、1分刻みで直せるようにする。既存の保存契約は変えない。

## 変更内容

- 日ごと表の出勤・退勤を、テキストだけに頼らず、時刻をボタンで選べる UI にする
- 日ごと表の休憩を、長さをボタンで選べる UI にする（既定 `01:00`、1分刻み）
- 保存時に送る値の形（`HH:MM`）と、API の拒否条件はそのまま
- Playwright は、新しい選び方でも値の確認と拒否ケースが通るように直す

## 対象能力

### 新規の能力

- なし

### 変更する能力

- `attendance-day-update`: 出勤／退勤の時刻選択 UI と、休憩長さのタイマー選択 UI を要求する。保存契約（前後関係、長さ、欠勤時は空など）は維持する

## スコープ

- 見本リポジトリ `wizway-kintai-demo` の画面入力と、それに伴う E2E
- 本番勤怠リポジトリと、本番の勤怠と同じ AWS アカウントは変えない

## 非スコープ

- 曜日表示・土日祝色の作り直し
- 研修用リポジトリ `wizway-kintai-demo-20261121` への機能追加
- 保存 API の契約変更、SQLite スキーマ変更
- DynamoDB、RDS、スライド作成

## リスク

- E2E が `.fill()` 前提だと壊れる → ラベルと値の契約を保ち、選び方用の操作に差し替える
- 曜日・行色の CSS／日付表示を巻き込むと研修済み題材が壊れる → 時刻セルと picker コンポーネントだけ触る

## 影響範囲

- `frontend/src/App.tsx`（必要なら小さな picker コンポーネントと CSS）
- `tests/e2e/attendance.spec.ts`
- API／DB は変えない想定。学習用 AWS への載せ直しは別指示のときだけ
