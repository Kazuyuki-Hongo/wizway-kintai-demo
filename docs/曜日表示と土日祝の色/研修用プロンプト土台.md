## 進め方（当日の型）

チャットは分け、各段のあとに人間が確認する。問題なければ次のチャットへ進む。

1. **要件定義チャット** … 要件定義書だけ。コードも実装計画も書かない  
   → 人間が確認
2. **実装計画チャット（別）** … 確認済みの要件定義書だけを渡す。実装計画書だけ。コードは書かない  
   → 人間が確認
3. **実装チャット（別）** … 確認済みの要件定義書と実装計画書だけを渡す。実装する  

同じチャットで要件→計画→実装を一気に走らせない。

---

## 1. 要件定義（Agents Window・このチャットだけ）

貼る前に言うこと（短く）: 「今から要件定義の指示を送ります。このチャットでは要件定義書だけです」

```
このチャットでは要件定義書だけを書いてください。実装計画もコードも書かないでください。

勤怠デモの日ごと表について、要件定義書を書いてください。

置き場: docs/曜日表示と土日祝の色/要件定義書.md
この案件では OpenSpec の change／specs は作らない。

やりたいこと:
- 日付の横に曜日を出す
- 土日と祝日の行は背景色を変えて一目で分かるようにする

書いてほしいこと:
- 何ができるようになるか
- やらないこと（時刻選択や休憩タイマーは別案件）
- UI の見え方（日付の形式、土曜と日曜・祝日の色の違い）
- API／DB を変えるかどうか
- 受け入れの目安

既存のログイン・保存・合計・CSV は維持する。
書き終わったら止まってください。実装計画や実装には進まないでください。
```

**人間の確認（このあと）**
- 日付の見え方と、土曜／日曜・祝日の色の分け方が書いてあるか
- やらないこと（時刻選択・休憩タイマー・OpenSpec）が切ってあるか
- 問題なければ、別チャットを開いて「2. 実装計画」へ

---

## 2. 実装計画（Agents Window・要件定義とは別チャット）

貼る前に言うこと: 「別チャットです。確認済みの要件定義書だけを渡して、実装計画書だけ書かせます」

```
このチャットでは実装計画書だけを書いてください。コードは書かないでください。

@docs/曜日表示と土日祝の色/要件定義書.md を正として、実装計画書を書いてください。

置き場: docs/曜日表示と土日祝の色/実装計画.md
OpenSpec の change／specs は作らない。

含めてほしいこと:
- 方針サマリ（何を足して、何を足さないか）
- 変更するファイルの一覧と、ファイルごとの方針
- 処理の流れと例外
- テスト観点
- Phase / Step（編集対象と完了条件、タスクチェックリスト）

Build は .cursor/rules/docs-spec-driven.mdc に従う。
書き終わったら止まってください。実装には進まないでください。
```

**人間の確認（このあと）**
- 変更ファイルと「触らないもの」が要件と食い違っていないか
- Phase / Step に編集対象と完了条件があるか
- 問題なければ、別チャット（IDE の Agent）を開いて「3. 実装」へ

---

## 3. 実装（IDE の Agent・要件定義・実装計画とは別チャット）

貼る前に言うこと: 「別チャットです。確認済みの要件と実装計画だけを渡して実装させます」

```
このチャットでは、渡した文書に従って実装だけしてください。仕様の再発明はしないでください。

OpenSpec は作らない。docs-spec-driven と Serena（initial_instructions → 編集前の構造把握）を使う。

ローカル E2E（意図的失敗テスト「わざと」は除いてよい）が緑になるところまで。
AWS への載せ直しは、指示があるまでしない。
```

**人間の確認（このあと）**
- 日付に曜日が出るか、土日祝の行色が分かるか
- Keep してよいか
